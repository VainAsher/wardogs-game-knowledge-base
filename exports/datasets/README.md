# Datasets

Machine-readable tables from the knowledge base, generated by `scripts/export_datasets.py`. Do not edit by hand. The KB docs stay the source of truth; every record names its source doc, section, doc version and confidence.

| File | Rows | Source doc | What it holds |
|------|------|------------|---------------|
| `meta.json` | 1 | both | Dataset version, game version, `sources_verified`, source docs (version, confidence, `review_due`), counts, notes |
| `items.json` | vendor price rows | `price-tables-season-1` | Price now and before, and whether the item is new, up or down (Update 0.2.0) |
| `unlocks.json` | role-track unlock rows | `progression-unlock-tables` | Unlock level and cost, now and before, per track, with moves between tracks |
| `xp_curve.json` | role-track XP rows | `progression-unlock-tables` | XP to reach levels 10 to 50, with the Season 1 source conflict flagged |
| `changes.json` | before/after rows | derived | Price, XP, unlock level and unlock cost changes, ready for a "what changed" feed |

## Statuses and nulls

- `status: verified` means the row comes from the official 0.2.0 notes via the KB doc. `status: conflict` means two official sources disagree on the old value; both are kept (`before` and `before_alt`).
- A `null` price, level or cost means the notes do not give it. Read the `*_status` field before treating a null as zero:
  - `level_status`: `stated`, `not_changed` (the notes did not change it, the value is not restated), `not_stated`.
  - `cost_status`: `stated`, `not_changed`, `not_stated`, `none`, `now_none` (it had a cost before, now none), `free`.
- `level_default: true` means the item is unlocked by default (no level). `level_prev_default` is the same for the old value.
- Money is whole in-game dollars. `xp` values are total XP to reach a level.

## Known limits

- `items.type` is only known for new items and attachments; it is `null` for other price changes. Item types come from other KB docs and are not joined yet.
- `unlocks.item_id` joins to `items.item_id` only when both docs use the same item name (about a quarter of rows). An alias map is future work.
- Combat, building and economy changes are prose in the docs and are not in `changes.json` yet.
- Season 1 baseline values are not exported; only 0.2.0 tables and the old values the notes print.

## Regenerate

```
python scripts/export_datasets.py            # write
python scripts/export_datasets.py --check    # exit 1 if the committed files are stale
python -m unittest discover -s tests         # tests
```

The exporter fails (exit 1) on any table row it does not recognise, so a doc edit that changes a table's shape is caught in CI instead of silently dropping data.
